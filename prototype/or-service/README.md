# Taipei OR 開發資料

本目錄獨立於現有 React 後台及 S01–S07 展示案例，已完成簡化 A 階段的優先排序與座標距離推薦，尚未實作 Gurobi 求解器、API 或跨端資料交換。

## 資料

- `data/taipei_base.json`：20 台車、24 件任務（13 清潔、7 現場維修、4 複檢）、6 名人員、12 個台北行政區示意點。
- `data/validation_summary.json`：資料結構檢查結果；不代表排程可行。
- `scripts/generate_taipei_data.py`：Python 標準函式庫產生器，固定種子 20261011，可重複產生同一份 JSON。
- `docs/model_plan.md`：A–D 建模計畫、限制、目標與輸出。

執行：`python3 scripts/generate_taipei_data.py`

規劃時間為 2026-10-12 台北時間 09:00–17:00，所有模型時間為相對 09:00 的分鐘數。負數停用時間代表規劃前已停用。車牌 DEMO-* 與所有人員均為虛構。

地點座標只代表台北各區周邊，不是經查證的 iRent 停車場或維修據點。交通使用直線距離乘 1.35、時速 22 公里及 5 分鐘到場緩衝，向上取整；同點為 0。矩陣對稱且固定，未使用導航或即時交通資訊，不能作為實際 ETA。

初版假設維修均可現場處理、人員搭服務車、工具不耗盡、每人班內需 30 分鐘休息（12:00–14:00 內完成，休息時停留當前地點），並於 17:00 前返回起點。班次結束為硬限制，任務期限為軟限制。這些均是模型假設，需由營運規則確認。

車輛恢復時間是整備任務完成的預估；人工放行等待時間尚未建模。安全異常不得由最佳化結果直接解除停用。工時、需求權重與預約全部為模擬值。

尚未安裝或驗證 Gurobi 授權，也尚未執行最佳化。

## 已實作：簡化 A 階段

從此目錄執行：

```sh
python3 baselines/stage_a.py
python3 -m unittest discover -s tests -v
```

輸出 `output/stage_a_recommendations.json` 與 `output/stage_a_report.md`。

1. 任務依 urgent → high → normal 排序，同級依完成期限、最早開始時間、ID。
2. 先篩選符合技能與工具的員工，再以員工固定出發座標到任務座標的大圓距離排序。
3. 每件任務獨立推薦最近合格人員，距離相同以員工 ID 決定；不更新人員位置、不套用指派。
4. 前置尚未完成、非待派或人工鎖定任務不推薦；無合格人員明確列出。

本版只做規則排序與距離推薦，不使用交通矩陣、不產生到場時間，不檢查班次容量、休息、任務時間衝突或是否已到最早開始時間，因此不能宣稱完整可執行排程。原資料的班次與交通假設留給 B–D。座標距離可先用於說明與比較，Gurobi 留至 B 開始使用。

## B：批次指派程式已建立，待授權驗證

`optimization/stage_b.py` 使用 Gurobi 建立二元指派與未派變數，限制技能、工具、服務工時容量及前置任務一起安排。目標依序減少 urgent／high／全部未派件數，再降低總起點直線距離。

執行：`python3 optimization/stage_b.py`。目前本機 Gurobi 授權過期，輸出僅為失敗狀態，不是求解結果。使用者已選擇先完成程式、更新授權後再求解。詳細公式、限制與待驗證項目見 `docs/stage_b.md`。

B 不含開始時間與路線，尚未扣除既有工作占用；只適合目前全新班次的假資料。A 與 B 共 12 項非求解測試通過。

## 最新：加入座標估計移動時間

使用者確認 22 km/h 與「起點 → 連續任務 → 返回起點」。執行 `python3 optimization/stage_b_travel.py`，以座標直線距離除以速度計算每段分鐘數，不加道路倍率或緩衝；工時包含服務、起程、任務間與回程。

20 項測試通過。台北案例 24 件全部指派，總路線 61.459 公里、移動 167.6 分鐘；30 秒達 TIME_LIMIT，尚未證明最優。結果見 `output/stage_b_travel_report.md`，限制與公式見 `docs/stage_b_travel.md`。仍未排開始時間、時窗、跨員工等待或休息位置，不是完整 C／D。
