# Stage C 工作量分擔

工作量定義為處理＋座標估計移動分鐘，不含休息與等待。以每位員工工作量除以其可用工時，考慮未來不同班次長度。

\[
W_k=\sum_i p_ix_{ik}+\sum_{(i,j)\in A_k}\tau_{ij}y_{ijk}
\]

新增最大工時使用率變數 \(U\in[0,1]\)：

\[
W_k\le (b_k-a_k-\delta_k)U\qquad\forall k
\]

新增一層目標：

\[
\min U
\]

目標順序改為 urgent 未派 → high 未派 → 全部未派 → 加權逾期 → 最大使用率 → 路線距離 → 提早完成。Gurobi 優先度分別為 40、30、20、15、12、10、5。

先保持任務服務量及期限表現，再降低最忙員工負荷，最後改善距離。分擔可能增加總移動；技能分布、工時長短或期限衝突可能讓部分人仍有較多任務。這是降低最大負荷，不是強迫每人相同件數，也不保證最大與最小的差距最小。

工作量未包含等待，因此與班次占用時間不同。排程限制仍檢查等待、休息與返回是否能放進班次。限時多目標求解的高層解未必已證明最佳，不能保證保留之前另一輪求解的逾期數值；應以本次各層結果和狀態評估。

原結果保存於 `output/stage_c_before_balance.json`，新結果與使用率表在 `output/stage_c_schedule.json` 和 `output/stage_c_report.md`。

新增小型測試：兩名相同技能員工與兩件各30分鐘、同點任務，模型應分給每人一件，而非全交給一人。
