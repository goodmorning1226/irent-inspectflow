# iRent InspectFlow 手機端 Prototype 分階段實作計畫

最後更新：2026-10-10  
文件狀態：第 1 階段已完成，等待使用者指示開始第 2 階段

## 1. 實作範圍與執行規則

本計畫只處理 Flutter 手機端 Prototype。後台端與跨端串接必須等手機端完成第 8 階段總驗證、取得使用者確認後，再另外規劃及實作。

手機端維持六個可選區域：車頭、左側、車尾、右側、前座及後座。只有左側車身與後座需要完整影片掃描互動；左側可由隱藏 Demo 控制器切換無損或有損結果，後座展示車內污損。其餘四區使用固定假資料呈現已完成縮圖與品質摘要。

手機方向採「一般流程直向、掃描流程橫向」：車況總覽、區域選擇、摘要、上傳及完成頁維持直向；使用者進入車外、車內或完工複檢掃描前，先顯示橫放手機提示，接著將 M06 至 M14 與完工重掃畫面鎖定為橫向。離開掃描畫面後立即恢復直向。Flutter Web 無法可靠控制實體螢幕方向時，需以橫向瀏覽器視窗呈現相同版面。

執行時遵守以下規則：

1. 只能依序進行第 1 至第 8 階段，不提前實作後續功能。
2. 每個階段都要等使用者明確指示，例如「開始第 1 階段」，才可以開始修改程式。
3. 每個階段完成後立即停止，回報變更檔案、可操作成果、驗證命令、驗證結果及已知限制，等待下一次指示。
4. 第 1 至第 7 階段只做格式化及靜態分析；只有靜態分析無法涵蓋的關鍵資料邏輯，才追加一個最小目標測試。
5. 第 8 階段才執行手機端完整總驗證、視覺檢查與展示演練。
6. 所有 AI、影像品質與異常判讀結果都由假資料及時間軸腳本產生，畫面必須標示「Prototype 模擬結果」。
7. 實作階段不得建立後台專案、Mock API 或跨端通訊；手機輸出只需形成未來可供後台使用的本機 JSON 結果。

## 2. 驗證策略

### 2.1 每階段輕量驗證

第 1 至第 7 階段原則上只執行：

- `dart format`，格式化本階段異動的 Dart 檔案。
- `flutter analyze --no-pub`，確認沒有靜態分析錯誤。
- 只有 JSON 解析、狀態序列化等無法由靜態分析判斷的關鍵邏輯，才執行一個最小目標測試。

第 1 至第 7 階段不製作驗證截圖、不做人工流程檢查、不跑裝置尺寸矩陣，也不重複執行完整 Widget Test。這些檢查統一集中到第 8 階段；若某階段的程式尚未完整可操作，將限制記錄在回報中即可。

### 2.2 最終完整總驗證

第 8 階段一次完成：

- 全專案 `flutter analyze`。
- 全部 `flutter test`。
- 六區選擇、四區固定摘要、左側無損、左側有損、後座污損、上傳、完成及重設的完整情境矩陣。
- 返回、重播、重設、影片結束、素材讀取失敗等重要操作。
- 至少三種手機尺寸的版面檢查，例如 360×800、390×844、430×932。
- 驗證直向總覽進入橫向掃描、離開掃描恢復直向的方向切換，並以對應的橫向尺寸 800×360、844×390、932×430 檢查掃描畫面。
- 離線執行與本機素材完整性檢查。
- Chrome 或可用 Flutter 裝置的完整展示演練；若 Android 工具鏈可用，再追加一次 Android Debug Build 或模擬器 Smoke Test。
- 依 3 分鐘影片預定路徑進行一次不中斷操作，記錄需要調整的等待時間。

## 3. 階段總覽

| 階段 | 實作主題 | 階段完成後可以看到什麼 |
|---|---|---|
| 1 | Flutter 骨架與視覺基礎 | 可啟動的 iRent 風格 App 外殼與 Prototype 標示 |
| 2 | 六區總覽與區域選擇 | 六區皆可點選；四區可查看固定完成摘要 |
| 3 | 影片掃描引擎與 Demo 控制器 | 同一套播放器可依 JSON 時間軸顯示提示、品質環與擷取事件 |
| 4 | 左側無損流程 | 左側掃描完成後自動擷取，且不觸發補掃 |
| 5 | 左側有損與補掃流程 | 同一區域可框出刮痕並完成近距離、多角度補掃 |
| 6 | 後座車內掃描 | 可框選污漬或遺留物並形成車內 Finding |
| 7 | 摘要、上傳、完成與完工複檢 | 手機端所有流程可從總覽走到送出，並可重設展示 |
| 8 | 整合、視覺收斂與完整總驗證 | 可穩定錄製展示影片的手機端定稿 |

## 4. 第 1 階段：Flutter 骨架與視覺基礎

**完成狀態：已於 2026-10-10 完成並通過階段輕量驗證。**

### 實作內容

- 確認 Flutter、Dart 與可用執行裝置；記錄版本及環境限制。
- 建立 `prototype/mobile/` Flutter 專案與基本目錄。
- 建立 App Router、共用 Theme、字型、色彩、間距及按鈕樣式。
- 建立淺色 iRent 流程頁與深色掃描頁兩種 Scaffold。
- 將一般流程預設鎖定直向，深色掃描 Scaffold 進入時鎖定橫向、離開時恢復直向。
- 加入全域「Prototype 模擬結果」標示。
- 建立最小假車輛、訂單與檢查工作階段資料。
- 首頁暫時只顯示車號、還車情境與「進入車況檢查」按鈕，不先做六區內容。

### 暫不實作

- 六區選擇、影片播放、異常框、上傳及任何後台功能。

### 輕量驗證

- 執行 `flutter pub get` 與 `flutter analyze`。
- 執行一個 App 啟動 Widget Test。
- 在一個主要開發裝置開啟首頁，檢查中文字型、紅色主按鈕及 Prototype 標示。

### 完成門檻

專案可由 README 指令啟動，首頁沒有錯誤或明顯版面溢位。完成後停止並等待「開始第 2 階段」。

## 5. 第 2 階段：六區總覽與區域選擇

### 實作內容

- 實作 M04 車況掃描總覽，顯示車頭、左側、車尾、右側、前座及後座。
- 六區皆可點選，並具備未開始、已選取、已完成、需補掃等狀態樣式。
- 左側與後座初始為待掃描；車頭、車尾、右側及前座由假資料預載為已完成。
- 實作 M04A 已完成區域摘要，顯示固定縮圖、完成時間及品質合格摘要。
- 返回總覽後保留選取區域與進度。
- 建立 `InspectionZone`、`ZoneStatus` 與檢查工作階段狀態模型。

### 暫不實作

- 左側與後座的真正掃描畫面；點選後可先進入功能尚未開放的乾淨佔位頁。
- 無損、有損及車內案例切換。

### 輕量驗證

- 格式化異動檔案並執行 `flutter analyze --no-pub`；互動、版面與完整流程留到第 8 階段驗證。

### 完成門檻

六區都能選擇，四個非展示區可查看完成摘要，左側與後座保留後續掃描入口。完成後停止並等待「開始第 3 階段」。

## 6. 第 3 階段：共用影片掃描引擎與 Demo 控制器

### 實作內容

- 建立可重複使用的掃描頁 Scaffold：頂部區域名稱、滿版影片、中央導引框、單一提示、品質環與底部縮圖列。
- 進入掃描前顯示「請將手機橫放」的短暫轉向提示；掃描頁採橫向資訊配置，離開時恢復直向總覽。
- 建立本機影片播放器封裝，不要求相機權限。
- 定義並解析時間軸 JSON：播放時間、掃描狀態、提示、品質值、擷取時間與相對座標框。
- 建立 `WAITING → ALIGNING → STABLE → CAPTURED` 基礎狀態機。
- Overlay 與影片分離，由 Flutter 元件即時疊加。
- 建立隱藏 Demo 控制器，可選案例、重播、跳到事件及重設；一般使用者畫面不顯示無損／有損選項。
- 先使用短版佔位影片與通用腳本驗證引擎，不在此階段完成正式情境。

### 暫不實作

- 刮痕判讀、多角度補掃、車內污損與最終上傳。

### 輕量驗證

- 格式化異動檔案並執行 `flutter analyze --no-pub`。
- 僅為時間軸 JSON 解析追加一個最小 Unit Test；播放、方向切換及視覺流程留到第 8 階段驗證。

### 完成門檻

更換影片與 JSON 即可重用同一掃描畫面，重播後事件順序一致。完成後停止並等待「開始第 4 階段」。

## 7. 第 4 階段：左側無損掃描

### 實作內容

- 加入 `exterior_clean` 影片、最佳影格與時間軸腳本。
- 從直向 M04 選擇左側後，經轉向提示進入橫向完整掃描畫面。
- 依序呈現對準、距離調整、保持穩定、品質鎖定及自動擷取。
- 擷取後顯示最佳影格縮圖與「未發現明顯異常」。
- 左側狀態更新為已完成，不進入補掃。
- 支援重播及返回六區總覽。

### 輕量驗證

- 格式化異動檔案並執行 `flutter analyze --no-pub`；無損流程、方向切換與重播留到第 8 階段驗證。

### 完成門檻

左側無損流程可穩定重播、自動完成，且不會出現異常或索賠文字。完成後停止並等待「開始第 5 階段」。

## 8. 第 5 階段：左側有損與局部補掃

### 實作內容

- 加入 `exterior_damage` 影片、廣角擷取影格、近距離影格及時間軸腳本。
- 由隱藏 Demo 控制器將左側結果切換為有損；一般使用者仍只選擇「左側」。
- 在指定時間與相對座標顯示疑似刮痕框。
- 實作 M10 至 M13：疑似異常、近距離補掃、中央／左／右三視角與補掃結果。
- 形成固定 Finding：位置、類型、嚴重度、可能新增、信心與來源影像。
- 結果頁只告知已取得補充影像、後續將由系統處理，不向會員顯示歸責或賠償。

### 輕量驗證

- 格式化異動檔案並執行 `flutter analyze --no-pub`；異常框、補掃互動及兩條案例分流留到第 8 階段驗證。

### 完成門檻

同一個左側入口可由隱藏控制器穩定呈現無損或有損流程，且兩條路徑不互相污染狀態。完成後停止並等待「開始第 6 階段」。

## 9. 第 6 階段：後座車內污損掃描

### 實作內容

- 加入 `interior_dirty` 影片、擷取影格及時間軸腳本。
- 從直向 M04 選擇後座後，經轉向提示進入橫向車內掃描版型。
- 導引框改為座椅與腳踏區輪廓，仍維持一次只顯示一項提示。
- 在指定時間框選飲料污漬、垃圾或遺留物中的一種主要異常。
- 形成車內 Finding，並將後座標記為已完成且待後續處理。
- 保持會員端文案中立，不顯示清潔費或責任判定。

### 輕量驗證

- 格式化異動檔案並執行 `flutter analyze --no-pub`；車內掃描流程與方向切換留到第 8 階段驗證。

### 完成門檻

後座可播放獨立車內素材、產生污損 Finding，且不誤用車外掃描輪廓。完成後停止並等待「開始第 7 階段」。

## 10. 第 7 階段：摘要、上傳、完成與完工複檢

### 實作內容

- 實作 M16 六區檢查摘要，整合固定完成區、左側結果與後座結果。
- 實作 M17 模擬上傳：逐項進度、一次可控制的失敗／重試及完成狀態。
- 實作 M18 完成頁，說明後續分析不需使用者原地等待，並可返回原 iRent 取還車流程示意。
- 建立手機端輸出 JSON，包含 session、zone captures、Finding、來源影像與 Prototype 標記，供未來後台沿用，但不進行傳輸。
- 實作展示重設，能清除本次狀態並回到固定初始案例。
- 實作 M19、M20 簡化完工複檢：沿用左側掃描引擎與固定完工素材，顯示原異常、同區域重掃及通過／需補處理結果。
- 摘要、上傳、完成及完工案件資訊維持直向；只有完工「同區域重掃」切換為橫向，結束後恢復直向。
- 補齊取車、還車與完工複檢三種入口的最低必要示意，不製作完整 iRent 其他頁面。

### 輕量驗證

- 格式化異動檔案並執行 `flutter analyze --no-pub`。
- 僅為輸出 JSON 必要欄位追加一個最小 Unit Test；上傳、重試、重設及完工複檢留到第 8 階段驗證。

### 完成門檻

手機端可獨立完成車況選擇、掃描、補掃、摘要、上傳、完成及簡化完工複檢，並能產生穩定假資料供後台使用。完成後停止並等待「開始第 8 階段」。

## 11. 第 8 階段：整合、視覺收斂與完整總驗證

### 實作內容

- 統一 iRent 紅色主操作、淺色總覽與深色掃描畫面的視覺層級。
- 修正字級、行高、觸控區、Safe Area、影片裁切、長文及小尺寸溢位。
- 精簡不必要動畫，只保留品質鎖定、自動擷取與異常出現等有功能意義的動態。
- 確認所有使用者文案採一致名稱，且不出現 Finding、scenario_id 等內部術語。
- 完成 README、操作說明、案例切換方式、素材來源與已知限制。
- 執行第 2.2 節的完整總驗證並修正發現的問題。

### 完整驗證情境

| 驗證路徑 | 必須確認的結果 |
|---|---|
| 六區選擇 | 六區皆可選；四區固定摘要正確；返回保留狀態 |
| 畫面方向 | 總覽與結果維持直向；進入掃描切為橫向；返回或完成後恢復直向；兩種橫向持握皆不溢位 |
| 左側無損 | 品質鎖定、自動擷取、無補掃、狀態完成 |
| 左側有損 | 異常框、近距離、三視角、Finding 與中立結果文案 |
| 後座污損 | 車內輪廓、污損框、Finding 與待處理狀態 |
| 模擬上傳 | 正常完成及一次失敗後重試成功 |
| 完工複檢 | 原異常、同區域重掃及結果狀態正確 |
| 展示控制 | 案例切換、跳轉、重播及重設可重複使用 |
| 裝置與離線 | 三種直向尺寸及其對應橫向尺寸無溢位，本機影片與 JSON 在離線環境可載入 |
| 產品邊界 | Prototype 標示存在；不宣稱實際模型準確率或自動歸責 |

### 完成門檻

- 所有完整驗證項目通過，或已知限制已記錄且不影響三分鐘展示主線。
- 可連續走完預定錄影操作，不需修改程式或人工修復狀態。
- 提交手機端完成報告與可執行方式，等待使用者確認手機端定稿。
- 未取得使用者確認前，不開始後台端或跨端工作。

## 12. 每階段固定回報格式

每完成一個階段，使用以下格式回報：

```text
階段：第 N 階段／名稱
狀態：完成／部分完成／受阻

已完成：
- 可操作成果

變更：
- 主要檔案與用途

驗證：
- 執行命令
- 通過／失敗結果
- 若有執行最小目標測試，列出測試名稱；完整人工路徑集中於第 8 階段

限制：
- 尚未處理、刻意留待後續階段或環境限制

下一步：
- 等待使用者指示「開始第 N+1 階段」
```

第 1 至第 7 階段不需要產生驗證截圖或完整測試報告；所有人工流程、視覺與尺寸證據集中於第 8 階段。
